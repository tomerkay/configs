# Prose a person reads is human readable

**Prose a person reads is human readable, wherever it lands**: a reply,
an assessment, a review and its findings, a plan, a commit subject and
body, an MR or PR title, description or note, a chat post, a markdown
doc, the description on a command's permission prompt, a run's report.
The reader has not opened the code and does not carry the session's
working words in their head - me after a break, or a teammate who was
not there - and each line is clear to them on one read.

- **Not code.** Code and its comments, config, commands, names chosen in
  code, branch names and output a tool reads keep their own conventions;
  only the prose around them is held to this.
- **What breaks it**: a name the session coined and never explained, a
  bare identifier where a description belongs, an abbreviation never
  spelled out, fragments joined by arrows or symbols.
- **Readable is not vague.** Where a line names a function, a key or a
  file, it also says in plain words what that is or does.
- **Plain beats short.** A length limit - one short clause, one line per
  item - is met by cutting detail, never by falling back on jargon.
