# Where my work lands

Which branch work lands on, its name, worktrees and backups are the
`tkay-code` skill's `branches.md`, in every session. What only my setup
adds:

**`~/.claude`, `~/repos/configs` and `~/repos/approve-no-look` are worked on
`main` by design**; every other repo is not.

**A worktree is never proposed.** When work belongs on another branch, the
proposal is a switch: the current branch's uncommitted work is committed or
stashed first, and restored after, and a run still going from that checkout
is named in the proposal.

**On a branch of my own, already pushed changes nothing**: I force-push my
branches, as "About Me and My Work" says, so a commit already on the remote
squashes and amends exactly like one that is not, and "it's already pushed"
is never a reason to make a new commit instead of amending, or to leave a
bad message standing.
